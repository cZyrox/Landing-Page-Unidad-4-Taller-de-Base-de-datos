Subtema 4.1

Conceptos Fundamentales

Principios del control de ejecución paralela y los conflictos que emergen por accesos concurrentes.

Concurrencia

Capacidad del Sistema Gestor de Base de Datos para procesar múltiples transacciones en paralelo compartiendo recursos sin interferencias.

Transacción

Unidad lógica e indivisible de trabajo que agrupa una o varias sentencias de lectura o modificación en la base de datos.

Integridad de Datos

Garantía de que la información almacenada se conserva precisa, completa y exenta de corrupción ante eventos concurrentes.

Problemas o Anomalías de Concurrencia

Dirty Read

1. Lectura Sucia

Ocurre cuando una transacción consulta registros modificados por otra transacción en curso que **aún no ha ejecutado COMMIT** y que posteriormente efectúa un **ROLLBACK**.

// Ejemplo:
T1: UPDATE saldo SET valor = 500
T2: SELECT saldo -> Lee 500
T1: ROLLBACK! (Cancela cambios)
T2 operó con un valor inexistente en disco.
Non-Repeatable Read

2. Lectura No Repetible

Sucede cuando una misma transacción realiza dos lecturas idénticas de un registro y obtiene datos distintos porque otra transacción **modificó o eliminó** dicho registro y confirmó los cambios.

// Ejemplo:
T1: SELECT precio -> $100
T2: UPDATE precio = $150 (COMMIT)
T1: SELECT precio -> $150
T1 obtiene dos estados distintos para el mismo registro.
Phantom Read

3. Lectura Fantasma

Ocurre cuando una consulta por rango de criterios arroja un número distinto de filas al repetirse, debido a que otra transacción **insertó o eliminó registros** y ejecutó COMMIT.

// Ejemplo:
T1: SELECT WHERE sueldo > 3000 -> (10 filas)
T2: INSERT nuevo empleado sueldo=4000 (COMMIT)
T1: Repite SELECT -> (11 filas!)
Aparecen nuevas filas en el conjunto de resultados.
Subtema 4.2

Propiedades de las Transacciones (ACID)

Los cuatro pilares esenciales que garantizan la máxima confiabilidad en el procesamiento de transacciones.

A

Atomicidad

«Todo o Nada»

La transacción debe completarse íntegramente o revertirse en su totalidad. Ante cualquier fallo, se ejecuta un ROLLBACK automático.

C

Consistencia

«Estado Válido»

Asegura que la base de datos pase de un estado consistente previo a otro estado válido posterior, respetando todas las reglas de integridad.

I

Aislamiento

«Independencia»

Mantiene invisibles las operaciones parciales de una transacción activa para otras consultas hasta que se concrete su confirmación.

D

Durabilidad

«Persistencia»

Garantiza que los cambios confirmados mediante COMMIT permanezcan inalterables de forma definitiva, incluso tras caídas del sistema.

Subtema 4.3

Grados de Consistencia

Niveles de restricción aplicados sobre los candados (*locks*) para evitar la corrupción de datos.

Grado 0

Sin Bloqueos

Permite sobrescribir datos modificados por transacciones activas. No se mantienen bloqueos de escritura prolongados.

Permite Lost Update
Grado 1

Previene Lost Update

Mantiene bloqueos exclusivos de escritura hasta el término de la transacción (`COMMIT`/`ROLLBACK`).

Evita sobrescrituras
Grado 2

Previene Lectura Sucia

Añade bloqueos de lectura mientras se consultan los registros, impidiendo leer datos no confirmados.

Sin Dirty Reads
Grado 3

Consistencia Total

Mantiene todos los bloqueos de lectura y escritura hasta finalizar formalmente la transacción.

Subtema 4.5

Control de Transacciones: Commit & Rollback

Comandos de control que definen la conclusión exitosa o la cancelación de una transacción.

COMMIT WORK

Consolida y guarda de forma **definitiva** en disco todas las operaciones ejecutadas durante la transacción, liberando los candados adquiridos.

ROLLBACK WORK

Aborta la transacción activa y **deshace la totalidad** de sus modificaciones, restituyendo la base de datos a su estado original.
